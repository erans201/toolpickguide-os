## 🔒 Security Guardrails
- **Never read, display, quote, or summarize the contents of `.env`** in chat responses, logs, notes, or any other file.
- **Same rule for `gsc-key.json`** (Google service-account key for Search Console): never open, read, display, copy, or commit it. Only `gsc_pull.py` / `ga_pull.py` load it at runtime, and **the user runs them**.
- **Same rule for `google-ads.yaml` and `ads-oauth-client.json`** (Google Ads API developer token, OAuth client, refresh token): only `kp_pull.py` loads them, and the user runs it. `kp-config.json` holds just the Ads account ID and is not secret.
- **Never attach secret files to the chat** (with + or @): attaching sends the full contents. If it happens, tell the user to rotate that credential.
- Never hardcode credentials in scripts or Markdown. Scripts load them from `.env` at runtime (e.g., `python-dotenv`).
- If `.env` values appear anywhere else (chat, notes, commit), stop and tell the user to rotate the WordPress application password.
- If git is initialized, `.env` must be listed in `.gitignore`.

## ✍️ Content QA Standards (QA Gatekeeper rulebook · user-approved 2026-10-01)
Applies to every in-house edit, every Junia brief, and every Junia draft QA. Source of voice: `brand-voice-sample.md`.
- **Length:** BOFU/MOFU 2,500–3,000 words · TOFU 1,800–2,500 words. **Applies only to new articles written in-house** (user clarification 2026-10-01). Not a limit for upgrades of existing live pages or for Junia drafts; there, trim only repetition, never for word count.
- **Structure:** bold-keyword hook in the first line → quick answer/ranking near the top → body → "don't mess this up" tips → 5–6 FAQs. One FAQ section only.
- **Pacing:** max 2–3 sentences per paragraph; conversational, direct, expert peer; analogies over spec sheets.
- **Banned words/phrases:** delve · testament · furthermore · in conclusion · in today's fast-paced world · unlock · game-changer · seamless · generic academic intros/outros.
- **Honesty:** never "tested", "hands-on", or "in our testing" unless real testing happened. No invented statistics, laws, ratings, or prices.
- **Facts:** every price/limit comes from a verified source (vendor pricing page or facts sheet) with a date; third-party figures are labeled. Junia may use only its brief's facts sheet.
- **Titles & keywords:** correct current year; focus keyword in title, first paragraph, one subheading, slug, meta description; numeric title claims ("60 questions") must match the content.
- **Links:** required internal links to live pages; official `**Source:**` links under pricing; FTC link in affiliate disclosures; every URL checked before adding.
- **Images:** no text, no logos, no brand names; inspect every image visually; keyword in alt text; host images in the Media Library (no hotlinking).
- **No cannibalization:** sitemap check before any new slug.

## 🌐 Website Manager: WordPress Publishing
- The agent does **not** log in to or write to the live WordPress site. Read-only public requests (sitemap, REST GETs without credentials, page fetches) are allowed for audits and for verifying changes after the user runs them.
- The upload tooling lives in the root folder: `upload_draft.py` (uploader), `make_featured_image.py` (featured images), `auto_scheduler.py` + `run_scheduler.bat` (scheduler). It pushes compiled Markdown (HTML, JSON-LD schema, Rank Math meta, tags, image) via the WordPress REST API.
- **The user runs these scripts manually.** The agent never executes upload scripts with `--upload`, and never runs `auto_scheduler.py` without `--dry-run`. Dry runs are fine.
- **Every article's Publishing Meta must include:** Focus keyword, Secondary keywords (`·`-separated), SEO title, Meta description, Slug, H1, Tags (comma-separated; prefer existing site tags), Category (existing categories only), Featured image alt, Pricing verified (starts with `YYYY-MM-DD`; drives the visible freshness line), and Affiliate domains (comma-separated, when affiliate links exist; they get `rel="sponsored nofollow"`). Don't use `---` separators for visual breaks; the uploader strips them anyway.
- **Featured images (user rule, updated 2026-09-29):** photo-style AI images (Junia or similar) are preferred over generated illustrations. Still **no text, no logos, no brand names**: reject images showing readable words or invented brands (e.g., "Canon", "Cangle"). Prompts live in `knowledge/briefs/image-prompts.md`. Save photos as `knowledge/images/<article-stem>-photo.(webp|jpg|png)`; the uploader prefers them automatically. `make_featured_image.py` illustrations are the fallback only. To push a new image to an already-upgraded live post, use `--force-replace --refresh-image`.
- **Junia.ai drafts (2026-09-29):** Junia is set to save **drafts only**. For each article the SEO Agent prepares `knowledge/briefs/junia/<slug>.md` (paste-ready prompt + facts sheet). Junia may use **only** numbers from that facts sheet.
